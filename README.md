# 漫画私藏 · ur-manga-web

选择最喜欢的漫画，生成个人推荐卡。默认 3 个漫画位置，可增加至 4 个；每本的长篇、中篇、短篇或同人类型由用户自行选择，允许重复或留空，搜索不会自动归类。旧版本收藏会保留原分类和已选的第 4 本。

源代码仓库：https://github.com/itoyohane/ur-manga-web

## 本地运行

使用 Node.js 22 或更新版本，无需安装依赖或构建。克隆仓库后运行：

```bash
git clone https://github.com/itoyohane/ur-manga-web.git
cd ur-manga-web
node dev.mjs
```

打开 `http://localhost:8000`。此服务同时提供 `dist/` 页面和 `/api/cover` 封面接口，与 Vercel 使用同一套封面处理代码。端口被占用时，先在原来的服务终端按 `Ctrl+C` 停止旧服务，再运行以上命令。切换后强制刷新网页，已保存的在线封面会自动重试。

可用 `PORT=8001 node dev.mjs` 更换端口。`python -m http.server` 只能预览静态页面，不能运行封面接口，因此不适合验证在线封面的 PNG 导出。也可用 `npx vercel dev` 验证 Vercel 部署环境。

## Vercel 部署

项目包含静态页面与一个 Vercel 封面函数，无需构建和 API 密钥。仓库根目录的 `vercel.json` 已指定发布 `dist/`，并跳过安装依赖与构建；根目录的 `api/cover.mjs` 自动部署为 `/api/cover`。仅上传 `dist/` 到静态托管不会提供此接口。

导入 GitHub 仓库时，Root Directory 保持仓库根目录（留空或 `./`），Framework Preset 选择 `Other`。将配置提交并推送到 Vercel 关联的分支后，部署最新提交。如果修改了 Vercel 项目设置，需要重新部署才能生效。

首页文件位于 `dist/index.html`；发布仓库根目录而未指定 `dist/`，可能导致首页返回 404。

## 使用

1. 点击漫画位置，在面板中自行选择类型；需要时点击“添加第 4 本漫画”。
2. 搜索作品，或手动输入书名、作者 / 社团并上传封面。没有找到时，可通过搜索结果下方的链接打开 Bangumi 漫画目录继续查找。
3. 可填写推荐理由，在“署名与介绍”中编辑卡片文字。
4. 查看实时预览，下载 1200 × 1600 PNG。

手机上使用双列选择卡片、底部下载按钮和底部选择面板。输入框使用 16px 字号，避免 iOS 聚焦放大；适配安全区，预览与署名直接展示。

## 界面样式

页面采用漫画手账风，使用奶油纸色、炭色文字、淡粉胶带与克制的玫瑰粉强调色。选择卡展示封面、书名、作者和推荐语；桌面左侧编辑、右侧大预览，手机纵向排列、双列选择，署名字段上下排列，底部固定下载栏。署名与预览无需展开即可查看。设计规则见 [DESIGN.md](./DESIGN.md)。

选择卡 16px 圆角，字段与按钮 12px，弹窗 22px；支持按压反馈、键盘聚焦、搜索骨架屏和减少动态效果设置。页面配色集中在 `dist/style.css`，推荐卡配色集中在 `dist/poster.mjs`。Phosphor 图标与生成的透明胶带均由本地 `dist/assets/` 提供，无新增运行时依赖。

导出的 1200 × 1600 推荐卡采用奶油纸面，按当前 3 或 4 个位置实时调整横栏间距，封面左右交替并轻微倾斜，使用编号与用户自选的浅粉分类标签、衬线书名、作者和推荐理由。仅保留顶部一段淡粉胶带。底部展示介绍和署名，默认介绍为“把喜欢的故事，认真收好。”。长文本自动换行或省略，封面完整缩放，不裁切；封面未准备好时可使用文字封面下载。

页面优先使用本机 Satoshi 或系统无衬线字体；推荐卡优先使用宋体 / 楷体，缺少对应字体时回退到衬线字体。无需远程字体请求，不同设备的字体外观可能略有差异。

## Bangumi 搜索

保留一个搜索框，支持书名、作者、标签，以及空格分隔的组合，如 `双人间`、`雪子`、`百合`、`百合 伊藤`、`伊藤 百合 日常`、`百合 双人间`。无需 API 密钥，数据均来自 Bangumi 官方接口：

- 完整输入交给 `POST /v0/search/subjects` 的 `keyword`，查名称与别名。
- 尝试用官方 `filter.tag` 查询标签及“名称＋标签”组合。
- 用 `POST /v0/search/persons` 搜索作者候选，再通过 `GET /v0/persons/{id}/subjects` 核对创作关系。
- 读取 `GET /v0/subjects/{id}` 的真实标签、封面和作者信息，核对“作者＋标签”组合；已取得的作品元数据会复用。

模糊匹配由 Bangumi 处理，前端不计算编辑距离、不维护作者别名或题材同义词表。空格分隔的词会作为名称、人物与标签候选尝试查询；标签按官方标签原文匹配。组合查询支持最多四个词、六种候选划分；超过四个词时保留完整名称搜索。人物候选按接口排序，核对创作关系后保留多位作者的作品，不擅自认定简称只对应某一个人。

按作品 ID 合并重复结果，展示名称、标签或具体作者等匹配依据；已核对的作者组合、名称与标签组合优先，名称查询保留 Bangumi 返回顺序。每页显示 20 部，可点击“加载更多作品”浏览本次已读取的结果。

输入停顿 700ms 后自动查询，支持中文输入法与单字搜索；新查询取消旧请求。成功数据缓存 5 分钟，部分失败的结果缓存 30 秒；手动点击搜索会重试失败分支，并复用成功元数据。部分请求失败时保留可用结果；搜索成功后不显示结果数量或读取限制说明，无结果或全部查询失败时显示提示。

为限制 API 负担，并发最多 3 个请求，单次最多 70 个请求、20 秒。名称和纯标签查询各读前 60 条，名称与标签的每种组合读前 20 条；每个人物查询取前 20 位，本次最多展开 12 位作者、轮流核对前 40 部关联作品。可输入完整作者名或具体书名缩小范围；这不能保证覆盖全部作品或与 Bangumi 站内搜索完全一致。

仅查询书籍并排除 R18；书籍可能包含漫画以外的书籍，选择时请核对。未收录的漫画和同人可手动添加。

## 数据与隐私

搜索关键词仅发送给 Bangumi。上传封面在浏览器中缩放，支持 JPG、PNG、WebP，最大 8 MB；上传图片和选择仅保存于当前浏览器。清除网站数据会删除本地收藏卡。

搜索选中的封面保留原始地址供页面显示，导出时优先经同源 `/api/cover?url=…` 获取图片，避免跨域读取限制。服务端仅获取 `https://lain.bgm.tv/` 下的封面路径，拒绝重定向，限制 JPG、PNG、WebP、4 MB 和 8 秒超时，成功响应可缓存。传给该接口的只有封面地址，不包含上传图片、推荐语或署名。

成功读取后，前端保存缩放后的本地副本供 PNG 导出。刷新页面和下载时会重试先前未成功导入的封面；读取失败或纯静态环境中，会尝试直接读取原图，仍失败时提示导出将使用文字封面。可直接上传或替换封面。原始图片也无法加载时显示失败提示。

实时预览在选择作品、替换封面或编辑推荐语时立即更新，未保存的修改仅用于预览，关闭面板会恢复已保存内容。预览优先显示本地副本，也可直接显示在线封面；PNG 使用独立 Canvas，仅绘制成功导入或上传的图片，避免预览中的跨域图片阻止下载。

旧版本已保存的条目如果没有封面地址，需要重新搜索选择一次，或直接上传封面。

## 目录与检查

- `dist/`：可直接托管的 HTML、CSS、原生 JavaScript 与 Canvas 图片生成。
- `dist/poster.mjs`：参考图样式的 Canvas 推荐图绘制与文字排版。
- `dist/search.mjs`：Bangumi 名称、标签和作者关联查询，结果合并、分页、缓存与取消处理。
- `api/cover.mjs`：Vercel 同源封面接口，仅允许 Bangumi 封面，不提供任意地址代理。
- `dev.mjs`：本地页面与封面接口服务，无第三方依赖。
- `tests/`：保存恢复、封面处理、Bangumi 请求契约与异常处理测试，使用模拟响应，不依赖网络。
- `.github/workflows/check.yml`：推送及 PR 自动运行语法检查和测试。

```bash
node --test tests/*.test.mjs
node --check dist/app.mjs
node --check dist/model.mjs
node --check dist/search.mjs
node --check dist/cover.mjs
node --check api/cover.mjs
node --check dev.mjs
node --check dist/poster.mjs
```

推荐 Node.js 22。JavaScript 使用两个空格缩进。测试不能替代移动浏览器实测；正式发布前应检查搜索、上传、恢复、PNG 下载及 iOS / Android 键盘布局。需要凭证的新服务应通过后端代理访问，不应把密钥写入前端。

API 文档：[Bangumi OpenAPI](https://github.com/bangumi/server/blob/master/openapi/v0.yaml)。
